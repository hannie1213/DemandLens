## Rules

1. **Strict time order**: train → val → test; all categories on the same UTC day fall in the same partition.
2. **Whole-month boundaries**: the last 2 calendar months = test, the month before = val, the rest = train.
3. **Non-overlapping evaluation blocks**: within val/test, cut consecutive 7-day blocks from the partition's first day
   as prediction intervals (matching the "next-7-day cumulative purchase" prediction target); trailing days shorter than 7 days
   get an empty `eval_block_start` and do not participate in evaluation, avoiding highly correlated adjacent sliding windows.
4. **No data snooping**: the split uses only calendar dates, never any event-value distribution; reproducible.
5. **Meaning of 7-day data**: taking 7 months (2019-10-01 .. 2020-04-30) as an example —
   train ≈ 2019-10-01..2020-01-31, val = 2020-02, test = 2020-03..2020-04.
   Under the longest 28-day input window, the earliest legal prediction origin within train is about 2019-10-29.
6. **Windows may cross partitions only into the past**: a val/test sample's input window may reference data from an earlier partition
   (that is history), but the target period (7 prediction days) never overlaps any other sample's target period,
   nor is it included in the input window (leakage is verified by M4's test_windows_leakage.py as a backstop).

## Fallback Rules When There Are Not Enough Months

- **4+ months**: follow the whole-month rule above (rule A).
- **Exactly 3 months**: m1 train, m2 val, m3 test (rule B).
- **Only 2 months** (the actual situation for the current multi-category store): m1 train, m2's first 14 days val,
  then test (rule C). val/test each have only 2 complete 7-day evaluation blocks, so evaluation power is limited;
  once more months are obtained, the split must be redone under rule A — this is the direct rationale for Phase-2 month extension.
  The cosmetics shop has 5 months and is already split under rule A (train = Oct–Nov, val = Dec,
  test = 2020-01–02, test contains 8 non-overlapping evaluation weeks).

## Why These Boundaries

- Formal experiments need at least four months (assignment 3.3): of the 7 months, 4 for training, 1 for tuning/selection,
  2 for final evaluation, covering 8 non-overlapping test weeks across seasons (winter→spring).
- Whole-month boundaries are easier to explain and reproduce in the report than "day-proportional" splits.
- val must also be evaluated with non-overlapping 7-day blocks: the tuning signal is consistent with the final test protocol,
  reducing the protocol bias of "best on validation ≠ best on test".
